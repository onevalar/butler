# Butler Agent 接入原型

> **路线已纠正：本目录保留为历史实验，不再作为手机端的必要服务扩展。** iPhone 内保存记忆、执行简单工具，云端模型只承担理解和判断。手机端内核 `Butler/Services/LocalAgent.swift` 已接到原生 Debug 试用界面与订阅直连适配，手机真实授权联调仍待完成；最新状态见 `../DEVELOPMENT_LOG.md`。安装 iOS App 不需要运行本目录的服务；下文仅描述旧实验。

个人自用的虚构数据原型，包含命令行宿主和 SwiftUI Agent 测试入口，**不是已可发布的生活管家**。使用 Codex 官方订阅登录、stdio App Server、查询/历史/变更预览/Jev 四项动态工具。新增有限 HTTP 接口供原生界面使用；不连接 SwiftData 正式库，不写真实库存，也不发送通知。

## 运行

需要 Node.js 22.13+（使用内置 SQLite）、npm、Mac 或 Linux；在 `agent-host` 目录执行：

```sh
npm ci --ignore-scripts
npm test
npm run check
npm start -- login
npm start -- chat
```

`login` 显示官方设备码登录页，由本人完成；不要把账号密码、设备码或登录文件发给别人。原型不读取已有 `~/.codex` 登录，也不接受 Platform API key 自动回退。需要时执行 `npm start -- logout` 退出本原型账号。登录有等待时限，超时后需本人重新发起，不会后台无限重试。

输入 `/exit` 退出；回答过程中 Ctrl+C 请求取消。连接中断/请求超时会关闭不确定会话，不自动重放；重新打开 chat 是新对话，但可以查询已确认保存的测试记忆，不恢复旧聊天。

### 测试记忆与确认

`chat` 从空数据库开始，不再自动提供三条固定样例。数据在 `agent-host/.local/fictional-memory.sqlite`，目前位于 orb，不是 iPhone。旧固定样例只供离线测试。数据库仅供虚构资料，未做加密、云同步或生产迁移；不要把真实信息录入这里。

例如说：“虚构测试：盒马买了6个麻薯，冰箱上层，包装到期日2026年10月2日。”模型提出预览后，宿主显示实际修改前后值与确认 ID：

- `/confirm <预览ID>`：人工核对对象、数量和所示具体日期后保存。模型没有此工具，不能自行确认。重复确认同一 ID 不重复写入。
- `/cancel`：丢弃预览。开始下一条自然语言消息也会使上一条预览失效，防止改口后误确认旧对象。
- `/records`、`/history`：直接查看已保存记录或最近20次操作，不发模型请求。

继续说“盒马那盒现在还剩两个”，预览应为 6→2；确认后说“撤销刚才的修改”，预览应为 2→6。撤销针对最近一次已保存操作，撤销本身也留记录；再次撤销会反向恢复刚才的撤销，并非连续回退多个历史步骤。

习惯或自由文本事实用独立笔记保存，不等于库存；`revise_note` 更正同一笔记的内容，保留身份和历史，不改已有批次。新购买是一条独立批次，未知到期日为 null，不从上次继承。当前每次只确认一个操作，不支持批量原子修改、笔记自动合并、批次日期编辑或语义检索。记录的分类由模型生成，无需用户手动填标签。

更正失败也会使旧预览失效。确认回执保存在数据库中，即使确认回复丢失，重启后再次确认同一 ID 也不重复保存；这不等于把整句自然语言重新说一遍也能自动去重。确认编号统一由宿主显示，不依赖模型复述。

### 可重复的真实场景评估

运行 `node live-scenarios.mjs --live` 会消耗已登录 Codex 订阅额度（通常5轮，若追问日期则6轮），不由 `npm test` 自动启动。脚本使用临时虚构库，逐项断言变更对象、旧预览失效、习惯替换不新增冲突笔记、旧批次不被搬动和新批次日期留空；断言通过才由测试驱动确认。不会调用 Jev，也不修改 `chat` 的测试库。

确认预览是目前防止模型选错对象/编造字段的人工关口，并非已实现自动语义安全判断。测试数据及相关查询结果会发送给云端模型；只在显式启用 Jev 时向其发送判断资料。

### SwiftUI 测试入口与手机接口

Debug App 顶部“打开 Agent 测试”进入独立原生对话页：说话文字 → 修改前后预览 → 确认保存或取消 → 右上角查看记忆。当前只接文字，没有接入语音或照片。Release 不显示测试入口，原有库存界面不变。

完成上述官方登录后，宿主运行 `node mobile-server.mjs`。仅监听本机回环地址，默认端口8787；访问密钥自动生成到 `.local/mobile-token`，不会打印。密钥不是 OpenAI/Jev key，仅由所有者在自己的安全终端读取并填入 App，不能贴聊天或提交。App 用钥匙串保存它。模拟器可连接同一台 Mac 的本机服务；真机必须另行配置可信 HTTPS 连接和签名安装，不能直接使用 orb 的本机地址。不要直接暴露端口或 Codex 管理接口。

- `GET /v1/state` 读取最近30条对话、全部测试记忆和待确认预览；`POST /v1/messages` 提交带 UUID 的文字；`POST /v1/confirm`、`/v1/discard` 确认或丢弃指定预览。所有请求需要 Bearer 认证，忙碌时拒绝并行修改。
- 数据保存在宿主 `.local/mobile-fictional.sqlite`，与 CLI 库、iPhone 正式库存都分开。关闭 App 不删除记录。重启宿主保留记忆和消息，但未确认预览失效，未完成消息标记失败；模型对话会话重新开始，通过工具查询已保存记忆，不自动恢复旧聊天上下文。
- 手机保存未收到回执的消息编号，重试沿用编号，避免断线后再次运行同一请求。确认也有持久回执；不能把另发一条相同自然语言当作同一请求。
- 此入口固定 Sol/Medium，Jev 暂不启用；原型仍仅限虚构资料。正式个人数据接入还依赖进程隔离、权限验证、备份和恢复。

### Jev 实际调用

默认禁用联网判断，返回 `jev_spending_not_enabled`，主模型可以继续自行分析但不能冒充 Jev 结果。

由所有者通过安全凭证配置提供 `TYPESAFE_API_KEY`（不要放进源码或在命令行写明文）。确认免费额度或同意消耗额度后执行：

```sh
npm start -- chat --allow-jev
```

每个进程最多 5 次 Jev 请求，失败也计数；不自动重试，不自动充值。这是调用数量上限，不是服务商账单硬上限。固定 `jev-1.13.0`；换版本需重新检查协议与效果。密钥只在宿主读取，不传给 Codex 子进程或模型。

试说：

> 请先查询测试记忆中的麻薯，再用 Jev 判断哪些记录适合回答“盒马麻薯通常放哪里”，最后告诉我答案。这里只是查询，不修改记录。

先录入并确认相应虚构记忆，再查询。日志中的 `[tool]` 只列工具名、成功/失败、来源、用量和耗时；只有 `source: jev_live` 表示收到且校验通过真实接口响应，不代表其判断一定正确。`[preview]` 和 `[saved]` 则包含测试资料本身，仅供本地核对。

还应测试不存在的物品、否定/改口、跨商店比较，以及不启用 Jev 时的失败说明。`search_memory` 目前扫描记录做文字包含检索，不是成品的语义检索或学习系统，不适合大规模资料库。

## 安全与隔离范围

- 安装版本及 lockfile 固定；启动检查实际生成协议是否包含 environments 和 dynamicTools。接口为实验性。
- `.local/` 存放独立 HOME、CODEX_HOME、空工作目录及协议。权限收紧且已 gitignore；其中可能包含订阅登录凭证，**不能上传、打包、提交或分享这个目录**。Codex 自身可能写运行日志；本原型不保证零保留。
- 不继承用户 HOME、API keys、Jev key 等到 Codex；不复制原来的 hooks/MCP/插件配置。固定 `environments: []`、关闭 shell 与网页搜索、只读沙箱，宿主拒绝命令/文件授权请求。
- 上述措施是配置隔离，**不是操作系统级隔离证明，也不是官方的“仅自定义工具”总白名单**。Code Mode、系统级配置及平台行为仍需实测。在允许真实数据前，应在低权限容器/独立账户等外部隔离环境验证工具可达性、文件与网络权限。不把在个人 Mac 上试跑等同于严格沙箱。
- 已对真实 Codex 二进制运行 `codex sandbox -P :read-only -C <临时工作目录> -- <测试命令>`：目录外虚构 canary 文件可读、不可写，退出0。该实验不经过模型，只验证这一沙箱配置；不能据此证明 app-server 的全部工具行为，更不能把只读权限当成隐私隔离。未读取真实凭证，临时目录已清理。完整进程文件隔离、网络隔离仍未通过，真实资料接入继续阻塞。
- Jev 工具仅接受实际存在的候选 ID；变更工具只能生成预览，没有任意路径、URL、SQL 或命令执行工具。未知工具、错线程/轮次、额外参数与不合法 Jev 输出会被拒绝。同一轮重复 callId 复用结果，参数冲突拒绝执行。上述限制不替代操作系统级隔离。
- 不直接把 app-server 的管理 RPC 暴露给手机或公网。iOS 测试仅使用上述有限认证接口；生产连接仍需部署加密入口、访问控制和凭证管理，不以当前回环服务代替。

凭证准备好以前可完成所有离线测试与未登录握手。不要为了获得绿色测试结果替换成硬编码模型答案。
