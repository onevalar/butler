# 水晶球交互设计约束

用户明确要求（2026-09-29）：水晶球按压和语音交互不得使用环形进度圈、环形倒计时、旋转等待圆弧或外围进度光环。后续修改不得重新引入这些表现。

按住说话（2026-09-29 更新，设计稿见 Paper「v12 长按说话」）：
- 手指会盖住水晶球，所以反馈不放在球心。按下立刻轻震一次，球向两侧鼓成两头半圆的圆条（不是尖的）；按住约 0.12 秒开始收音，圆条拉宽，两侧出现随真实音量起伏的声条，上方出现文字气泡和“松开发送”。
- 同一时间只出现一处文字：上方一个气泡（没听到时写“松开发送，上滑取消”，听到后就是识别文字），取消只写在红色区里（“✕ 取消”，进入后变“松开取消”），不叠提示胶囊。
- 上滑不是冒出一个新按钮：红色取消区从同一块玻璃上长出来，用一根柱子般的颈部相连，不做成中间细的工字形（`VoiceGeometry` 是一个整体轮廓，圆条底边不能有凸起）。手指进入红色区并松手才取消；往下、往左右滑都不取消，也不打断录音，滑回来红色区收回。
- 收音先于识别：麦克风先录、声音先存着，识别就绪后按顺序补上，不丢按下后说的话（`AudioRelay`）。
- 按住不到 0.4 秒就松手且什么都没听到，按轻点处理：打开对话，不弹“没听清”。
- 水晶球背后不加任何圆形底框，包括对话页顶部的小球。
- 反馈只来自球本体的形变、两侧声条（真实音量，不模拟）和上方文字。准备录音用文字说明；支持松开取消与减少动态效果。

2026-09-29 简化更新（取代此前滚动落下/摊开方案）：
- 水晶球是位置、形状和操作含义稳定的入口；滚动不触发掉落、摊开或聚拢，不要求先聚回成球才能对话。
- 保留轻点对话、按住说话、真实音量和上滑取消反馈。触觉使用离散状态：触碰的柔和轻震、麦克风真正就绪的清晰确认、进入/离开取消区的选择反馈、交付语音的成功反馈。不得用固定计时假装录音已经就绪。用户随后明确要求准备期间连续反馈，见下方更新。
- 触碰反馈在手势回调中直接触发并预热生成器；音频会话允许录音期间触觉，减少动态效果时仍保留触觉。模拟器不能验证马达手感，必须明确区分自动化通过和用户真机确认。

2026-09-29 再次真机反馈后的按压更新：
- 用户要求接触瞬间反馈，准备期间可以持续震动或频率渐快；采用原生 touchesBegan 立即轻震，加逐渐加快的短脉冲，取代仅一次轻震后静默等待。
- 准备脉冲由 Core Haptics 预调度，间隔从约220ms递减到120ms，温和强度且不无限加速；不支持时退回系统反馈。最多5秒，超时停止并提示重试。
- 真正录音启动由 LiveDictation 的直接回调通知，立即停准备脉冲并确认；不能等 SwiftUI onChange，不能凭阈值时长宣告开始收音。松手、拖离、失败、后台、页面退出一律停止；减少动态效果不禁用必要触觉。
- 环形进度圈及倒计时禁令继续有效。马达体感必须以真机反馈为准。

2026-09-29 连续取消/重按回归要求：
- 原生触摸入口由系统 UILongPressGestureRecognizer（minimumPressDuration=0）管理识别与复位，触碰反馈仍在 touchesBegan 直接触发；不要自行用裸 UIGestureRecognizer 写 began/ended 状态循环。
- 每次按压使用独立会话标识。上次准备超时、录音就绪、动画完成和语音收尾的延迟回调不得修改后一次按压。
- 取消必须释放录音和忙碌状态；触觉引擎停止/重置后下次按压重新准备播放器。语音收尾最多等待3秒，超时解锁入口并保留未发送文本提示。
- 验证必须包含同一页面连续“按住→上滑取消→立即再次按住”至少3次，以及准备中取消后重按。状态单元测试、模拟器无障碍点击都不能替代这条真机触控验证。

2026-09-29 紧急恢复（覆盖上面原生手势/准备脉冲的实现约束）：
- 用户报告原生识别器修正版按压完全无响应；手机日志无touch began，只有interaction reset。撤回OrbTouchGesture，自定义识别器不再进入应用；恢复原有SwiftUI DragGesture(minimumDistance: 0)与GestureState取消处理。
- 同时移除Core Haptics准备脉冲播放器，使用不操作音频引擎的UIKit轻震。连续/渐快触觉仍是用户未完成的体验需求，不能宣称已实现；先保证按住、取消、再次按住可用，再独立验证增强。
- 每次会话隔离、取消清理、收尾超时保护保留。水晶球仍固定，不恢复滚动掉落/摊开，不恢复环形进度。今后不得凭纯状态单元测试或无障碍点击通过就宣布长按真机通过。

2026-09-29 连续触感独立试用（用户同意先独立验证）：
- 正式 OrbDock 暂维持恢复后的实现。新方案在“管家与设置 → 交互试用 → 按住说话 · 连续触感”全屏隔离，使用独立录音对象，不发送对话、不修改数据。真机体验确认前不替换正式入口。
- 试用入口仍用 SwiftUI DragGesture，不再引入原生自定义识别器。球本体轻微受压、两侧真实音量；不做球/条/光晕多段变形，不使用进度圆圈。
- 触碰只启动一段 continuous haptic，真正开始收音时约45ms淡出，没有第二次ready震动，也没有松手成功震动。取消边界保留选择反馈。不支持连续触觉时只降级一次系统轻震，不能延迟补播。
- 触觉引擎在打开试用页预热，使用独立音频会话、haptics-only。单段最长0.8秒后安静等待，防止授权/异常时无限震；准备5秒、收尾3秒超时释放状态，触感长度不是录音进度。
- 已有44项相关回归（含8项真实控制器配合模拟录音对象的取消/重按/超时测试）；模拟器只确认入口、布局和退出。物理触摸复位、马达连续性、收音噪声必须另在手机验收。

2026-09-29 独立试用页首次触感延迟修订：
- 用户实测按下到起振仍迟钝。上版日志只有按压处理后与录音就绪时间，不能据此断言唯一原因。试用页录音就绪约0.6秒，首次触感必须独立于这段等待。
- 仅试用页用标准UIControl的beginTracking/continueTracking/endTracking/cancelTracking承接触摸；不使用此前失效的自定义UIGestureRecognizer，也不修改正式OrbDock。退出与系统取消须同步复位。
- 引擎就绪后和上次松手后提前创建pattern/player，按下回调先调用feedback.begin，不在此时创建播放器。单段连续事件起点即明确强度，再柔和稳定，不加独立第二下，不等录音就绪才反馈。
- 记录系统触摸时间戳至控件回调的延迟、反馈调用耗时与录音启动时间；这些只能定位软件延迟，不能当作物理马达开始时间。

2026-09-29 用户确认触感后接入正式入口（当前有效）：
- 用户确认试用版震动可以，并要求同时支持短按输入、长按语音。正式OrbDock与试用页共用VoicePressControl、VoicePressInteraction和ContinuousPressFeedback，不再使用正式入口原来的SwiftUI拖动/双次UIKit震动。
- 接触立即播放已预备的同一段触觉。小于0.3秒且未明显移动的松手打开当前上下文对话并聚焦文字输入；按住达到0.3秒提交语音意图并启动麦克风。一次按压只走一条路径，长按空语音、失败和取消不能退回文字入口。
- 长按松手整理并发送一次，上滑取消，滑回继续；准备和收尾超时、后台、视图退出清理保持。短按不请求麦克风权限，明显拖动后松手不误作短按。
- 正式球保持原位，只轻微受压；录音时两侧真实声条，上方正文状态与取消提示。删除原来的球/鼓包/圆条多段变形，持续保持无圆形进度。
- 已确认的是试用页马达手感。正式入口的物理短按/长按、上下文发送与连续取消仍需安装后真机验收；53项自动化及模拟器文字入口检查不能替代该验收。

2026-09-29 纠正擅自简化视觉（覆盖上一节“删除多段变形”）：
- 用户明确指出只要求纠正震动，不应移除既有液态玻璃和流动感。调整触觉不等于授权删减视觉设计；保留原始玻璃表面、折射、内部流光、按压鼓起/拉宽和一体化流动取消区。
- 恢复原OrbStage、LiquidSurface、BallLight和VoiceGlass绘制。它们只负责视觉，不挂手势或sensoryFeedback；已确认的VoicePressControl、ContinuousPressFeedback与短按/长按控制器保持独立，控件全程挂载，不随视觉切换销毁。
- 松手的回弹完成回调必须校验视觉会话，不能隐藏后一次按压；后台/退出立即清理。恢复的是液态视觉，先前已经取消的滚动掉落/摊开、禁止的环形进度不恢复。
- 聊天输入区刚去掉的整块背景、分隔线和等待提示仍保持去掉，不应随视觉恢复一起回滚。

2026-09-29 自定义语音识别：
- 默认苹果识别；设置可选自定义 OpenAI 兼容音频转写服务。自定义录音结束才上传，取消不上传；录音时显示真实声条，不伪造逐字结果。等待转写可取消。
- 收尾期限按本次录音选择的服务确定：苹果3秒、自定义45秒；不得以原来的3秒本机收尾期限提前取消网络请求。旧会话的迟到结果不能发消息或影响下一次录音。
- 本轮只改文案和识别后端，不修改用户确认的触觉、液态玻璃或短按/长按分流。

2026-09-29 实时语音追加（用户明确选择 gpt-live-transcribe）：
- 此模型走 WebSocket 实时转写，不能发到文件转写接口；准备网络期间缓存有限音频，确认会话配置后顺序发送，松手 commit 后仅交付最终结果。
- 实时取消会断开连接并丢弃文字，不能宣称已上传音频可撤回；上方液态视觉和即时触觉继续保持原实现。
- 音频转换对象可能在音频线程销毁，明确使用 nonisolated deinit，避免隐式主线程析构崩溃；转换与客户端取消都要有回归测试。

2026-09-29 设置页清理：用户确认连续触感已接入正式入口，“交互试用”入口从设置页移除；试用页与 Jev 自动对照测试只在 Debug 构建且以 --dev-tools 启动时出现在“开发者测试”分组，普通安装不可见。

2026-10-07 语音动效连续性修订：
- 球、拉宽圆条、上滑取消区由同一个持续挂载的玻璃表面绘制；接触后一次连续展开，不在长按阈值处停到鼓包后再启动第二段。
- 反射、流光、描边、声条位置跟随同一插值宽度，取消区从圆条内部连续长出；不在按下/松手时替换两套玻璃视图。短按/长按判定、真实音量、已确认触觉不变。
- 动画流畅度仍须真机触控验收，编译和几何连续性回归不能替代实际帧率或马达体验。

2026-10-08 水晶球变形残影修订：
- 禁止在拉宽的玻璃下叠加一个完整 ButlerOrb 再按进度淡出；这会出现“外框先展开、中央圆球消失”的双层假象。
- 正式入口只有一条玻璃外轮廓，深度、原有 Metal 流光、顶部反光与底部折射都随相同宽度伸展，不能保留独立圆形边界或额外球体阴影。声条在轮廓接近展开后显现，音量仍只来自麦克风。
- 触摸控制器、短按/长按阈值、触觉及发送/取消逻辑不变。Debug 启动参数 --preview-orb-morph 仅循环绘制展开/取消区/收回，不开麦、不发消息，供逐帧视觉检查；不能替代真实触摸与音量验收。

2026-10-08 对话色彩修正：默认玻璃主题的背景/按钮填充必须使用明确动态 label 色，不用可能继承前景环境的 .primary；文字用反色 systemBackground。禁用反馈只在实际不可操作时生效。
