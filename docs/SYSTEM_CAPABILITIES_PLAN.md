# Butler 系统能力扩展清单

基线：2026-09-29，`main` 的 `548b900`。本文是**待实施清单**，不是已交付功能或 TestFlight 状态；完成一项时记录实际代码、权限、构建、真机和分发结果。目标是在苹果公开接口、设备条件和用户授权允许的范围内，持续扩大 Butler 能做的事，不将首批范围视为永久上限。

## 已有能力与共同做法

- 已有：Butler 自己的任务及本地通知、只读系统日历、天气与按需定位、相机/选取照片、语音、库存 Spotlight 索引、用户选择的文件导入和备份。`ButlerWidget/` 有源码，但工程尚无 Widget target；不能算已安装的小组件。
- 现有对话通过 `ButlerTools` 提出修改、展示确认卡、确认后调用 `ReminderStore` 等执行。新增系统写入复用业务操作及任务对象的 ID/版本检查；系统弹窗是**另一层**授权，模型不能替用户点击。Siri/快捷指令等新入口应调用同一业务操作和授权规则，可使用系统确认而不强制返回 App 确认卡。
- 每项接入先明确「数据从哪里来 → 要改哪个系统对象 → 何时确认 → 系统回执/外部 ID → 失败后如何恢复或取消」。请求成功不等于闹钟响了、通知送达或外部设备执行了；需要分别观察。只在用户启用对应场景时申请该项权限，拒绝后保留可用的本地功能。
- 修改现有提醒或外部对象时，先读最新值；重复调用、取消、App 被终止、权限撤销和外部修改均不能造成重复创建或误删。隐私资料只按本次任务所需提供给模型；健康、联系人、家庭设备资料及云端同步另有明确说明与开关。

## 审查补充与执行约定（2026-09-29）

以下约定与逐项验收要求共同执行；勾选的代码工作不等于云端构建或真机验收通过。

- **交互确认**：用户已授权逐项开发内部功能；新增或改变界面交互必须先讨论并确认。能够独立完成且不预设交互的内部工作直接推进。开发授权不等于推送、云构建或部署授权。
- **第一项的依赖前移**：AlarmKit 只要支持倒计时展示，就需要相应 Widget extension，不以是否自定义样式为条件；缺失可能导致不响铃。这部分不等第 6 项桌面小组件才实现。
- **闹钟语义**：停止本次响铃、稍后再响、取消后续闹钟、完成整个任务是不同动作，不能关闭响铃就完成任务。重复闹钟要明确旅行后跟随当地时间还是保持原时区，不静默转换原有任务的时区规则。拒绝闹钟权限后不自动降级通知并声称成功。
- **统一规则，不强制统一页面**：App Intents 可在 Siri/快捷指令流程中请求系统确认；简单操作不必强制回到 Butler。复杂修改再打开 App 核对，所有入口执行同一参数、对象和版本校验。实际交互仍需用户确认。
- **对象关联恢复**：日历事件移到另一日历时标识可能变化。失去链接后重新读取核实，不能直接认定已删除而重建；不能唯一确认目标时停止写入。验收增加事件移动、重复事件拆分和同步后的关联恢复。
- **健康读取限制**：HealthKit 刻意不允许判断某类读取权限是否被拒绝；授权流程完成不等于所有类型均获准。空结果只说明没有可读取记录，不能推断未运动或权限已拒绝。按实际 SDK 支持处理有限历史访问，锁屏不可用与空数据分开处理。
- **健康资料隔离**：个人资料交给第三方 AI 前明确告知接收方、用途和范围并获得许可。按苹果规则排除个人健康信息进入 Butler 的 iCloud 同步，包括含相关内容的聊天、笔记、附件和备份，不能只过滤原始健康样本。
- **实时活动边界**：普通 ActivityKit 活动最多活跃 8 小时，结束后锁屏可能再保留最多 4 小时；用户移除展示不等于取消任务。超过时限的任务回到普通任务管理；不把普通实时活动限制直接推定为 AlarmKit 闹钟限制。
- **进度与恢复从第一项开始**：保存每次系统写入的操作进度、目标和回执，区分待执行、成功、失败和结果待核实。系统已经写入但本地回执没保存时，恢复后先对账，不盲目重试。多步骤操作分别报告结果，不把部分成功说成全部完成；不能撤销的动作明确说明。权限检查在实际执行入口生效，不只依赖模型指令或页面。
- **跨设备执行归属**：同步任务不等于每台设备都再执行一次；为闹钟、通知及外部写入确定执行设备，区分本设备系统标识和跨设备任务标识，验收双设备不会重复创建或无意同时响铃。

依据：[AlarmKit 扩展要求](https://developer.apple.com/documentation/alarmkit/scheduling-an-alarm-with-alarmkit)、[App Intents 确认](https://developer.apple.com/documentation/appintents/appintent)、[日历标识变化](https://developer.apple.com/documentation/eventkit/ekevent/eventidentifier)、[健康授权限制](https://developer.apple.com/documentation/healthkit/authorizing-access-to-health-data)、[实时活动时限](https://developer.apple.com/documentation/activitykit/displaying-live-data-with-live-activities)、[审核规则 5.1.2 / 5.1.3](https://developer.apple.com/app-store/review/guidelines/#privacy)。OpenMinis 参考 [2026-09-29 源码](https://github.com/OpenMinis/OpenMinis/tree/b4c0661d5631ebab4d1a2e6f3fd4c805d4030a6c)：通讯录实现未核实，MediaPlayer 不等于完整 MusicKit，实时活动不等于桌面小组件；不照搬默认放行或后台保活策略。

## 逐项交付（尚无新增能力完成交付）

顺序表示依赖与优先实施顺序，不表示后面的能力可省略；硬件、账号或家居设备不具备时，该项代码仍可完成，但真机验证要标明缺失条件。每项先在独立变更中实现、测试、验证，再处理下一项。

### 1. 真正响铃的 Butler 闹钟 / 计时器 — AlarmKit

- [x] **已确认交互并接入源码**：不新增闹钟页面、表单或选择器。主模型按对话意图区分普通通知、响铃闹钟和倒计时；有歧义先询问，复用原确认卡和文字确认。设置、查询、修改、取消都通过对话。系统权限弹窗仍由用户操作。
- [x] 增加 `get_alarm_capabilities`、`get_alarms`、`propose_alarm`、`propose_alarm_action` 四个工具，覆盖一次、每周任选日期（七天即每日）、1 秒至 24 小时倒计时、完整替换、取消/启用、停止本次响铃、倒计时暂停/继续。一次闹钟保留固定时刻；每周规则明确跟随手机当地时间。查询剩余时间不可用时返回未知，不用初始时长冒充。
- [x] 加入用途说明、AlarmKit 适配和倒计时扩展 target。确认后请求权限；写前保存本设备操作记录，取消旧闹钟经读回确认后再创建新版本。结果不明保留待核实记录；查询只对账，不重建消失的闹钟。重复确认、旧版本、过期操作、拒绝权限和存储失败均有拦截。闹钟记录排除备份，不进入现有导出数据；断网备用通知解析不接管明确的响铃要求。
- [ ] 将闹钟与 `ReminderStore` 任务建立明确关联，处理任务改期、暂停、完成和撤销。当前闹钟独立存储，停止响铃不完成任务，完成任务也不会自动取消闹钟。复杂多阶段规则、跳过单次重复、节假日、每周固定异地时区和未来开始日期尚未接入；不能把这些意图静默简化成每周重复。
- [ ] 验收：真机设定一次/重复闹钟并实际响铃，静音和专注模式下检查系统行为；修改、暂停/完成任务及撤销后旧闹钟不再响；拒绝授权、重启和跨时区后显示准确。它是 Butler 拥有的系统闹钟，不承诺修改「时钟」App 的原有闹钟。

### 2. 苹果「提醒事项」 — EventKit

- [ ] 增加独立的系统提醒事项读取、创建、改期、完成、删除入口；申请提醒事项权限，选择目标列表，确认卡写明列表、标题、截止时间/重复条件。保留 EventKit 标识与 Butler 任务的链接，但**默认不把所有现有任务自动复制过去**。
- [ ] 对已链接对象从系统重读、处理用户在「提醒事项」中的外部编辑；明确一个任务是「仅 Butler」「仅系统」还是「已链接」，避免重复通知。位置提醒另核实定位权限；无法等价表示的 Butler 多阶段规则不静默降级。
- [ ] 验收：在「提醒事项」App 看见新建内容并可改期/完成，Butler 重开后反映外部变化；重复确认无重复项，权限拒绝和源对象被删除时有清晰结果。

### 3. 系统日历写入 — EventKit

- [ ] 在现有只读 `CalendarFeed` 旁加入创建、改期、删除事件的操作；为写入更新当前只描述「只读取」的授权说明，选择日历和时区，校验起止、全天/跨日、重复范围及冲突。系统日历是事实来源，不复制事件为 Butler 日程再自动双写。
- [ ] 使用现有确认卡逐次展示时间、地点、日历与通知设置；保存外部标识，编辑前读最新事件，遵守用户在日历 App 做的修改。
- [ ] 验收：在系统日历创建/修改/删除可见；重复事件选择「单次或后续」正确；拒绝授权、无可写日历、跨时区/夏令时和并发外部编辑不误操作。

### 4. Siri / 快捷指令 / 操作按钮入口 — App Intents

- [ ] 将安全、边界明确的 Butler 动作（查看今日安排、添加待核对物品、打开指定任务、完成指定任务）暴露为 App Intents / App Shortcuts；复用现有业务校验。简单操作通过系统确认，复杂修改再打开 Butler 核对；具体交互先经用户确认，不在后台代替点击。
- [ ] 使用稳定任务/物品标识并处理对象已删除、手机锁定、未授权及重复触发；动作可由用户组合到快捷指令和设备支持的操作按钮。
- [ ] 验收：真机在快捷指令和 Siri 中发现并运行指定动作；同一操作从 App 和快捷指令进入结果一致，取消确认不产生写入。App Intents 不授予对其他 App 的通用控制权。

### 5. 从其他 App 分享给 Butler — Share Extension

- [ ] 给 Xcode 工程增加分享扩展 target；通过单独的 App Group **传输收件箱**接收用户主动分享的文本、URL、图片和文档。现有 SwiftData 数据库暂留原位，不因启用 App Group 就搬迁；必要时只共享小份待处理数据。
- [ ] 对订单、网页、小票、照片保留来源及原件或可重访引用，解析失败仍可在 Butler 收件箱看到并手工处理；成功核对后才写入库存/任务。处理扩展被系统中断、冷启动、重复分享和大文件。
- [ ] 验收：从浏览器、相册、文件 App 分享到 Butler，断网/中断后不丢不重，未确认前不改库存；权限/格式不支持时说明原因。分享扩展不能后台扫描其他 App 的全部内容。

### 6. 桌面 / 锁屏 Widget

- [ ] 把现有 `ButlerWidget/` 真正加入 Widget extension target，配置 App 和扩展共同的 App Group 与签名；先做小而稳定的只读快照或迁移过的共享投影，不直接把已有数据库移动到 App Group。展示今日待办、临期物品，并加可审计的快捷动作。
- [ ] 验收：真机添加/移除小组件，离线、重启、深浅色和旧数据升级后内容正确；完成操作不重复写，目标不存在时不显示过时结果。

### 7. 锁屏 / 灵动岛实时活动 — ActivityKit

- [ ] 在 Widget target 上增加正在执行的有限时任务/倒计时状态；创建、更新、结束与 Butler 任务生命周期一致。明确本地可更新的场景；跨设备或持续远程更新要另设计服务器推送，不把实时活动当作后台常驻进程。
- [ ] 验收：任务完成/取消后活动消失，App 退出和屏幕锁定时显示不自相矛盾；不支持灵动岛的设备用锁屏状态验证。与 AlarmKit 倒计时展示可共用 target，但分别核验。

### 8. 健康数据 — HealthKit

- [ ] 配置 HealthKit capability 和用途说明，按具体场景申请读/写类型（如查看活动趋势、记录用户确认的饮水或营养）；对话只拿到本次所需摘要，不把整个健康档案默认交给云模型。区分建议、用户陈述与真正写入的健康记录。
- [ ] 写入前显示数据类型、值、单位和日期；保存来源标识，允许纠错/删除 Butler 自己写的记录，不修改无关来源的数据。
- [ ] 验收：授权/撤销、部分类型授权、空数据、重复写入、单位换算及删除在「健康」App 可核对；真机检查隐私与锁屏状态。

### 9. 家庭设备 / 场景 — HomeKit

- [ ] 配置 HomeKit capability 和用途说明，读取获授权家庭的房间、设备与可操作属性；先支持明确设备的读取，再支持开关和场景执行。设备离线、同名设备或不支持写入时先解释，不猜目标。
- [ ] 用户首次及高风险动作显示房间、设备、预期变化并确认；传回实际执行结果，不把发出命令说成设备已改变。
- [ ] 验收：有 HomeKit 家庭的真机上验证读取、开关、场景、设备离线和撤销授权；无设备环境时只能算自动化测试通过，不能算真机链路已验收。

### 10. 通讯录 — Contacts

- [ ] 按需请求联系人访问或使用系统联系人选择界面，先做按名称查找与消歧，再做经确认的创建/修改。只把已选择联系人的必要字段用于当前任务，不上传整本通讯录。
- [ ] 验收：同名、受限授权、外部修改、重复创建与撤销权限；在系统「通讯录」中核对写入，不将联系人能力误表述为自动读取信息、通话记录或短信。

### 11. 兼容的蓝牙设备 — Core Bluetooth

- [ ] 配置蓝牙用途说明；先扫描/连接、读取设备与服务，再针对**已确认协议的 BLE 设备**增加特征值读写。未知设备不得按猜测写入控制命令，不把系统蓝牙开关或所有耳机/家电当作可控设备。
- [ ] 验收：至少一台真实兼容外设的配对、断连、权限拒绝、超时和写入后读回；无外设时不标记为已完成真机验收。

### 12. 地点与出行 — MapKit / Core Location

- [ ] 在现有仅用于天气的按需定位之上加入地点搜索、路线/预计抵达时间、从日历地点或任务地点启动导航；出行建议与写入提醒分开确认。仅在明确的地理围栏场景评估后台定位权限、数量和电量影响。
- [ ] 验收：定位拒绝时可手选出发地，异地同名地点先消歧，跨时区的出发提醒与地图预计时间一致；不开定位仍可使用库存/任务。

### 13. NFC 物品标签 — Core NFC

- [ ] 配置 NFC 读取能力；先扫描用户贴在盒子/柜子上的标签并关联 Butler 物品或存放位置，写标签另行明确确认。标签只含随机 ID，不写入私人库存或密钥；丢失/重复标签可解绑或重绑。
- [ ] 验收：支持 NFC 的真机扫描、重复读取、未绑定标签、权限/设备不支持及误绑定恢复；不把 NFC 当作无需接近设备的自动定位。

### 14. Butler 数据跨设备同步 — CloudKit

- [ ] 先盘点 SwiftData 库、`reminders.json`、笔记、图片、会话和备份的所有权与现有迁移测试；制定稳定 ID、版本、删除记录、冲突解决和端到端恢复方案，再逐类开启私有 iCloud 同步。不同于系统日历/提醒事项的各自同步，CloudKit 只同步 Butler 自己的数据。
- [ ] 默认保持现有单机数据可用；可选择启停同步，离线写入、双设备并发、账号切换和权限失效均不丢原数据。不要与 Widget 的 App Group 数据库迁移绑成一次发布。
- [ ] 验收：两台设备或两个受控测试环境创建/编辑/删除、离线重连、重装恢复、账号切换与旧数据升级，逐条核对无静默覆盖。

### 15. 媒体播放 / 更多用户主动输入

- [ ] 评估 MediaPlayer/MusicKit 对授权音乐库的检索和播放控制：优先做播放/暂停当前可控媒体，曲库搜索与指定曲目播放按服务与权限分开实现；不能承诺控制任何其他 App 的私有播放队列。验证无媒体服务或曲目不可用时的结果。
- [ ] 在现有照片选择、相机和文件导入基础上，逐个加入用户主动选择的 PDF/票据、从分享扩展来的链接等真实输入；限定文件大小和格式、保留来源、先预览后进入库存/任务。若需访问整个照片库，应另设使用场景与权限，不能把 PhotosPicker 等同全库权限。
- [ ] 验收：真实媒体设备/账号上验证授权和播放回执；多文件、损坏文件、重复导入、网络失败时不丢原件也不自动写正式资料。

### 16. 内置网页读取与操作

- [ ] 基于应用内浏览器支持导航、读取、填写和操作，不承诺操控 Safari 或其他 App 界面。先确认登录、人工接管、执行预览与确认交互；网页内容是不可信资料，不能覆盖用户指令或取得新授权。
- [ ] 按网站限制 Cookie、凭据和数据使用；付款、提交、删除等重要动作确认实际目标与参数。提交后结果不明先核实，不重复点击；遵守目标服务条款。
- [ ] 验收：登录失效、验证码/人工接管、页面变化、恶意网页指令、重复提交、断网及跨站数据泄漏防护。

### 17. 外部服务连接 — 官方 API / MCP

- [ ] 优先接入有明确场景的官方 API 或远程 MCP（外部工具连接协议），按服务、账号、工具和数据范围授权。密钥进入安全存储，不进入模型上下文、日志或普通备份；支持撤销连接。
- [ ] 外部工具描述和结果不能自行授权执行；重要写入同样需要确认和回执。超时可能已经执行，不能一律重试；按服务支持采用防重复请求标识或读回核实。
- [ ] 验收：至少一个真实授权服务的读取和写入、账号切换、授权过期、工具变化、撤销、超时核查和越权拒绝。真实账号连接与外部写入另外授权。

### 18. 授权文件夹与受限制的文件处理

- [ ] 支持用户选择的文件夹内查找、整理、生成和导出，使用系统授权引用，不承诺全机文件访问；先确认覆盖、删除、预览与撤销交互。
- [ ] 另做脚本执行可行性验证，评估本地受限环境或用户授权远程端，以及发行规则、许可、资源与成本；不照搬 OpenMinis 的 Linux 环境，不把内部脚本等同宿主 iOS Shell。脚本不能绕过文件或系统能力授权。
- [ ] 验收：授权失效、文件移动、路径越界、只读目录、同名覆盖、大文件、中断恢复；脚本若落地，增加时间/内存、网络范围和取消验证。

### 19. 自动任务与中断恢复

- [ ] 区分系统负责的闹钟/通知、App 内尽力执行的任务、服务器执行的定期查询/条件检查；逐任务说明锁屏、强退、断网时的保证。不能以静音音频或无关定位保活，也不承诺指定时间唤醒任意 AI 工作。
- [ ] 记录触发条件、执行设备、进度、上次结果、重试和取消状态；错过时间按明确规则补做或跳过，不无限补跑。服务器只执行已授权远程能力，不能假定可以唤醒手机调用任意本机 API。
- [ ] 验收：执行中终止、恢复、重复触发、部分成功、超时结果不明、取消后仍返回、跨时区和双设备重复执行。服务器部署、费用与账号条件另行确认。
